Operação Interface Resgatada

O app já funciona. Sua missão não é reconstruí-lo: é encontrar barreiras, melhorar a interface e provar que outra pessoa consegue usá-la sem explicação.

0 / 100 XP
Regra da campanha: XP é formativo, não é nota. Usar dicas não tira XP. A missão só conta quando há evidência e explicação.

M1 · Scanner de Barreiras

8 min15 XPDIAGNOSTICAR

Objetivo: Observar antes de editar. Registrar pelo menos 3 barreiras reais na interface que já funciona.

  1. Abra o app e use-o por 60 segundos sem alterar o código.
  2. Registre pelo menos 3 barreiras em docs/AUDITORIA_INTERFACE.md: leitura, toque, semântica, cor/estado ou imagem.
  3. Para cada barreira, escreva uma evidência observável: “não há feedback quando pressiono”, “não sei se o controle tem 48 dp”, etc.
  4. Escolha apenas 2 barreiras prioritárias para corrigir primeiro.
Dica 1

Não procure sintaxe ainda. Observe o comportamento.

Dica 2

Compare “funciona” com “consigo perceber, operar e compreender”.

Dica 3

Se tudo parece perfeito, peça ao colega para usar sem você explicar.

M2 · Laboratório de Layout

18 min30 XPORGANIZAR

Objetivo: Usar Image local, View, StyleSheet e Flexbox para melhorar leitura e distribuição sem mexer na regra de negócio.

  1. Adicione a imagem local fictícia já fornecida no projeto — não busque foto real na internet.
  2. Crie um grupo visual com Image + textos usando View.
  3. Use Flexbox conscientemente: experimente row/column, alignItems, gap e flex e observe o resultado.
  4. Aumente hierarquia/legibilidade sem alterar props, estado, filtro ou seleção.
  5. Teste no navegador antes de avançar.
Dica 1

A imagem deve resolver organização, não decorar.

Dica 2

Um View pode agrupar imagem e textos; outro pode deixar os textos ocuparem o espaço restante.

Dica 3

No React Native, flexDirection padrão é column. Para imagem ao lado de texto, teste row e flex: 1 no grupo textual.

M3 · Toque que Responde

21 min35 XPOPERAR

Objetivo: Dar feedback perceptível ao toque, tamanho adequado ao controle acionável e semântica acessível à ação.

  1. Identifique o controle realmente acionável da sua trilha. Não transforme cartão informativo em botão falso.
  2. Adicione feedback durante pressed usando a função de style do Pressable.
  3. Garanta alvo de toque compatível com a referência Android de 48 × 48 dp no controle acionável.
  4. Dê papel e nome acessível à ação. Use hint apenas se o resultado não ficar claro pelo label.
  5. Confirme que estado importante continua explícito em texto e não depende apenas de cor.
  6. Teste em um Android real quando disponível.
Dica 1

Na trilha EDA, o botão é o filtro; os cartões são informativos.

Dica 2

Pressable pode receber style como função que fornece pressed.

Dica 3

accessibilityLabel deve nomear a ação de modo contextual, não repetir “botão”.

BOSS · Boss Fight — Teste Cego

12 min20 XPVALIDAR

Objetivo: Outra dupla usa a interface por 60 segundos sem explicação; vocês registram uma barreira e corrigem uma delas.

  1. Troque de dupla. A dupla visitante tem 60 segundos para usar o app sem receber explicação.
  2. A visitante responde: “o que parece acionável?”, “o toque responde?”, “algum estado depende só de cor?”, “há algo confuso ou apertado?”.
  3. A dupla autora registra UMA barreira real em docs/TESTE_CRUZADO.md.
  4. A autora corrige UMA barreira imediatamente e mostra a mudança ao colega.
  5. O colega confirma se a correção tornou a tarefa mais clara.
Dica 1

O visitante não pode pedir dica durante os 60 segundos.

Dica 2

Feedback útil descreve a barreira observada, não “ficou bonito/feio”.

Dica 3

Corrija apenas uma barreira agora; registre as demais para depois.

Entrega final

  1. Faça uma captura do antes e outra do depois.
  2. Registre a barreira encontrada no teste cego e a correção realizada.
  3. Execute npm run conferir e npm run contraste.
  4. Faça um commit descritivo.
  5. Preencha o ticket individual.
